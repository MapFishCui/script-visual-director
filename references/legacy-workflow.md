# 原布局优先流程：执行协议

仅在已有项目记录或用户明确选择旧流程时读取。新九宫格项目不执行本协议。

## 旧完整项目：开始工作

将包含 SKILL.md 的仓库根目录记为 `SKILL_ROOT`，用户指定的资产输出目录记为 `PROJECT`；两者不同。遵守当前工作区的输出目录要求。阅读 [操作与数据约定](asset-schema.md)。若 `.venv` 不存在，按该文件创建项目虚拟环境后安装锁定依赖；不要向系统 Python 安装依赖。

使用 `SKILL_ROOT/.venv/bin/python SKILL_ROOT/scripts/svd.py` 调用工具；Windows 使用 `.venv/Scripts/python.exe`。所有后续相对输入路径均相对于资产项目，文件路径包含空格时正常引用。

用户只有一句描述也可开始：保留原文，标记 `explicit`、`inferred`、`proposed`。缺少风格时先提出代表方案；会改变剧情、血缘或已确认设定的信息才集中提问，不逐项追问普通设计细节。

## 旧流程的工作顺序与确认

1. 收集目标视频系统、具体模式/版本、画幅和目标时长；图像生成工具独立选择。目标未定时可先做通用分析与分镜。按目标官方指南适配格式；没有专用语法时使用推荐提示词结构，不自称官方格式。MiniMax-H3 只是适配目标之一。选用 H3 时先读 [官方 skill 接入](h3-official-skill.md)，按素材实际用途路由模式；正文编译支持范围与官方能力分开说明。
2. 先阅读 [二次创作](creative-development.md)、[叙事与摄影](narrative-and-camera.md) 并形成剧情与角色依据。在审核页面编写用户所说的“中文导演稿”：逐镜的场景、镜头运动、人物运动，附时长、台词语气与必要创作依据；它已包含拍法提案，不是另加一份必需的散文稿。按 [创作与取舍](directing-practice.md) 先构思再整理字段，不为填表加戏。初始化 review-init --workflow layout-first-v1 并打开 review-serve；可先以空镜表展示进度，再用 review-storyboard 首次导入真实中文稿。先让用户确认这份中文导演稿，程序用 analysis 阶段记录确认并绑定正文版本；此时不要求先编译系统原文。三项正文遵守 [写作规范](three-part-storyboard.md)，摄影描述在人物动作之前。
3. 中文导演稿确认后，按 [平面图与白模流程](layout-first-workflow.md) 和 [空间规划](spatial-planning.md) 制作平面图，确定结构、物件、通道、人物初始位置并让用户确认。中文稿的摄影与行动为设计依据，空间不成立时回修中文稿。观察机位和不属于特定镜头的路线可用 shot=null。
4. 平面图确认后询问生成／跳过整场调度白模，用户已明确选择则沿用。按 [整场白模协议](layout-first-workflow.md) 用观察机位展示连续行动、事件顺序和物件交互，可辅以中文稿提出的摄影机视角；此时是在验证拍法与行动，不先锁定最终剪辑。blocking-* 命令与后面的逐镜预演分别存档，先诊断帧后完整 MP4，实际检查后让用户确认。白模精度以比例、关键结构、可辨认姿态、必要接触与遮挡为准，不只移动方块。 必须按 [现成三维资产库](model-library.md) 查找、下载留存与锁定合适的人物和物件；模型导入、视觉检查和用户批准分开记录，不默认重新拼人体。 需要把导演稿转成统一场景、行动和摄影机时，读取 [场面计划执行](scene-execution.md)，优先 scene-compile / scene-bind；缺失动作返回 blocked，不以默认站姿或平移替代人物表演。 可复用 [建模组件](modeling-components.md) 的结构、骨骼 IK、接触点与检查器，先读取其能力边界和坐标约定；失败须修正并重跑，不用笼统的“启用碰撞”代替几何验证。跳过须记录原话与未验证范围。
5. 白模确认或明确跳过后，核对中文导演稿与实际空间、行动，修订受影响内容，然后编译供目标系统执行的最终分镜及逐镜中文对照。场面可有省略、停留、不同观看距离，不把观察录像直接切段。H3 使用 [官方规范](h3-handoff.md) 及 scripts/h3.py，明确参考来源与用途；素材尚未生成或绑定时仍标为待绑定稿。按 [导演检查](director-review.md) 核对完整段落与转换，提交用户确认最终分镜。无需重新建立镜表或审核项目。按 [导演组与任务](generation-groups.md) 同时确认导演组及内部生成任务，H3 的单任务限制从任务规划起检查，不限制整场白模或导演组长度。
   最终分镜确认后，可按 [逐镜摄影机预演](local-previs.md) 输出各镜审核与纯摄影机 MP4，用户也可跳过。整场调度白模不直接冒充逐镜 H3 运镜参考。生成后再核对参考与最终文本；中文稿或空间、调度实质修改会使相关确认过期，单纯系统文本转换不会撤销上游中文稿与空间确认。
6. 前置确认齐备后确定资产需求、所需角度与状态。一个镜头不必一张资产。先生成人物、场景、关键道具基准，确认后扩展。场景资产必须按 [预演到场景资产](scene-reference.md) 绑定布局版本、预演机位方向与几何形态，核对门窗、家具、通道和遮挡，不凭气氛另造空间。人物默认交付四张独立图：颈部以下正视、含头部背视、含头部左侧视、头部特写；共用同一人物基准与纯白棚拍背景，保留四张原图并附每人一张原尺寸四视图合图供下游使用，制作时阅读 [人物四图规格](character-reference.md)。家庭角色阅读 [家庭设计](family-design.md)，按亲缘依赖顺序制作；不是所有项目都需要家庭设计。
7. 阅读 [生图与检查](image-production.md)，用 queue 检查依赖后调用实际图像工具，查看结果并 register/review。approve 或 approve-gate 只记录真实用户依据，质量检查不替代批准。
8. 更改用 revise 保留旧版；中文分镜修改必须同步系统文本，检查邻镜和空间/资产影响。阅读 [交互审核](interactive-review.md) 处理“确认”“继续”“同步修改”，读取已保存进度，无须在同一对话重新调用 skill。跨对话按用户给定项目路径恢复。
9. 核对已确认逐镜预演与分镜，逐镜说明各参考素材的用途与保留范围；将确认后的真实图片顺序与版本绑定至目标格式，按当前模式重新核验，执行 validate --strict 后正式打包。MiniMax-H3 阅读 [H3 交接](h3-handoff.md)；其他系统同样验证实际导入方式。导演台交付另按 [生成分组](generation-groups.md) 绑定公共与组内素材、按任务检查输入限制，每个导演组独立执行 groups-package，或用 groups-bundle 输出全部独立导演包；不能把通用 manifest 冒充原生工作流。阶段包使用 --draft，明确未完成事项。

## 旧流程审阅入口

HTML 审阅页贯穿分镜、分组、布局、预演、基准、扩展资产和交付，不在后半段退回只报文件路径。每次提交待确认内容或完成交付时，先登记真实文件与当前状态，再检查 `/api/state` 和相关文件可读，用当前环境的浏览器打开工具打开或刷新同一项目页面，并给出可点击的审阅 URL。工具不可用时明确说明，提供用户可打开的 URL 与启动命令；只有磁盘路径不算已展示审阅页。服务在运行所在机器的回环地址启动；换电脑必须在新机器启动，不能复用旧机器的端口和令牌。

用户回复“确认／继续”时先读取 review/state.json、分组状态与 manifest，沿已确认版本继续当前阶段；不要重建审核项目，也不要把完成预演当作完成全项目。每轮简短说明本轮结果、待确认对象及下一步；用户要求暂停资产时保留暂停。基准确认后继续四张独立人物图及所需场景／道具变体；导出后仍回到审阅页展示资产与交付文件。具体展示和恢复方式见 [交互审核](interactive-review.md)。
