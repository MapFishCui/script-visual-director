# 人物参考资产：四张原图与四视图合图

每位需要建立人物参考资产的角色，默认交付以下四张独立图片。使用同一个已确认的人物身份基准，保持脸型、发型、年龄感、服装、体型、身高比例和材质状态一致。已有的全身人物基准可以继续作为生成参考，但不能替代这四项交付。

| 视图 | 文件后缀建议 | 构图要求 |
| --- | --- | --- |
| 颈部以下正视图 | body_front | 身体正对镜头，画面上缘在颈部下方自然裁切，不包含头部；双手、躯干、腿和双脚完整可见。是取景裁切，不是生成无头人体或抹去头部。 |
| 含头部背视图 | body_back | 人物背对镜头，从头顶到脚底完整呈现；头部朝向与躯干一致，不回头露出正脸。 |
| 含头部左侧视图 | body_left | 人物自身的左侧面朝向镜头，呈严格侧视；包含头顶、躯干和双脚，不用斜前方三分之四角度代替。头部与身体朝向一致。 |
| 头部特写 | head_closeup | 完整展示头顶发型、脸部、耳部及颈肩上缘，面部朝正前方、表情自然，便于核对身份与五官。不是只裁眼睛或嘴部。 |

## 生成与确认

1. 完整项目先完成该流程所需前置阶段与人物身份基准确认。按需人物图遵循 [按需交付](on-demand-delivery.md)，无需分镜、布局或白模；指定单张／视角只做所需图片。扩展图仍使用同一身份基准，未确认版本不能记为已确认。
2. 同一角色的四图引用确切的同一基准版本。先检查头部特写的身份一致性，其他含头视图必要时同时引用该特写；侧背面造型的未定信息按原基准合理延续，不擅自增加服饰、伤痕或配饰。
3. 每项使用独立资产编号、独立生成调用与独立文件。四张原图分别留存；下游默认使用每人一张四视图合图，合图不替代可编辑的原图底稿。
4. 使用相同纯白无缝摄影棚背景、柔和中性照明和接近的机位高度。背景不能包含剧情场景；其他纯色或透明背景仅按明确要求制作。全身视图保持相近尺度与留白；头部特写按身份识别需要单独取景。服装干湿、污渍及袖口应一致。
5. 用 asset dependencies 引用同一角色基准及必要的已检查头部特写。人物基准变更时沿依赖标记旧视图失效，用 revise 生成新版，不覆盖历史文件。

## 逐图检查

- 正视图：头部不入画、裁切自然、双手双脚完整，正面服装细节符合基准。
- 背视图：头部完整、发型后部及服装背面合理，未变成人物回眸或背部三分之四视角。
- 左侧视图：确实是人物左侧，鼻尖与身体朝向一致，比例和衣服厚度无异常。
- 头部特写：五官和年龄感与基准一致，发际线、耳部与颈肩自然，无多余人物。
- 四图共同检查：同一身份、服装、体型与材质状态；每项真实生成、视觉检查、用户确认分别记录。

表情变化、手部特写、右侧视图或其他服装状态，根据已确认分镜另行增加，不用它们替代上述四图。若用户明确修改交付规格，遵循用户的新要求并记录差异。


## 纯色背景约束

人物身份、服装或体型参考图，无论按需单张、基准图、局部图还是完整四图，均使用纯白无缝棚拍背景；张数和工作流不构成背景要求的例外。用户明确指定其他纯色或透明背景时遵循其要求。只有用户明确要求剧情画面、环境人像或保留场景时才带环境，且不能把它冒充纯背景人物资产。剧本提到某种环境不等于要求人物参考图带该环境。

人物参考图是棚拍设定资产，不是剧情画面。生成提示词先声明这一用途，再描述角色与所需视角，最后明确背景；不要直接将整段剧本当生图提示词。冬装、泥渍、湿衣等属于角色状态，不代表应生成雪地、泥地或雨景。

通用约束示例（各平台按实际工具方式传入，不假设有负面提示词参数）：

> 单人物摄影棚设定参考图。保留参考人物的身份、年龄、服装和体型，只采用本次要求的视角。人物位于纯白无缝背景前，背景与地面连成一体，无地平线、无纹理，柔和均匀的中性棚灯。全身视图脚底仅允许极淡接触阴影。画面中没有户外景物、建筑、家具或装饰，没有文字、水印或边框。剧情环境不进入这张参考图。

生成后实际查看背景：有雪地、树木、山景、室内陈设、明显环境倒影或彩色环境光时不通过。必要时引用原图，只要求移除背景并保持人物，编辑后重新核对身份、轮廓、手脚及衣服；仅写提示词不能宣称已得到纯白背景。截图或聊天缩略图不是原始资产，不把它们当四图原文件。合图工具不会自动抠背景。

## 合图与像素保存

完整人物资产在四张原图检查后，默认附一张 PNG 合图；指定单图任务不因此扩展。固定 2×2 顺序：左上颈部以下正视、右上含头背视、左下含头左侧视、右下头部特写。一张合图只包含一个角色，不混放不同人物。不加面板标签、水印或装饰边框，区域含义写入提示词。

使用现有虚拟环境运行：

```sh
.venv/bin/python scripts/character_sheet.py --front /绝对路径/front.png --back /绝对路径/back.png --left /绝对路径/left.png --head /绝对路径/head.png --output /资产输出目录/character-sheet-v001.png
```

工具只排版真实原图，不生成或重绘人物。按 EXIF 方向读取，各格按最大宽高补白居中，不缩放、不拉伸、不裁切。四张1024×1024得到2048×2048；尺寸不同则总画布可能因补白大于原图像素之和。保存 PNG 防止新增有损压缩，无法恢复原图已有压缩损失。来源 JSON 保存四图哈希、原尺寸和区域坐标；其中绝对来源路径是本机追溯记录，跨机交付需携带原图并使用项目相对绑定。现有输出拒绝覆盖。输入应是色彩一致的8位图像；该工具不是色彩管理转换器。

检查最终图片和区域记录后再用于下游。合图以派生资产登记，依赖四张原图的确切版本；原图变化需重新合图并更新任务绑定。按需任务可直接交付 PNG 和来源 JSON，完整项目仍按 manifest 登记、检查并通过既有打包校验。合图不自动获得批准。实际上传占一个图片槽位；四张底稿不自动随它再占四个槽位。H3 输入可能缩放，原尺寸合图不保证模型处理时保留所有像素。

## H3 人物定义

每个角色合图绑定一个实际 Picture 槽位；不能把四格定义成四个人。下面仅是 subject_definitions 中的一条示例，替换成真实槽位，其他章节仍按官方规范编译：

```text
<Subject 1> is the single character shown in the four-panel reference sheet <Picture 1>. The top-left panel shows the body from the front, cropped below the neck. The top-right shows the full body from behind, including the head. The bottom-left shows the full body from the character's left side, including the head. The bottom-right is a head and face close-up. All four panels show the same person in the same outfit. Use the bottom-right for facial identity and hairstyle, and the body views for proportions and clothing. The neck crop does not mean the character has no head.
```

中文对照应完整说明上述区域与用途。在 retention_analysis 中保留该人物的身份、服装与体型；不要要求保留参考图的纯白背景、静止姿势或四格排版。正文按剧情指定真实场景，生成正常单画面视频；动作引用同一 Subject，无需每镜重复区域定义。只有作为人物外貌来源时，不额外定义独立 Picture 条目。此写法是本项目按官方格式编写，不是官方四图标准，也不保证模型完全隔离参考属性。人物局部不清时可额外绑定头部原图，并重查9张图与混合素材总量限制。
