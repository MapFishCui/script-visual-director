# 家庭基准与确认关卡

先区分称谓、血缘和外貌要求。剧本没有说明血缘时不自动归为亲生；可提出普通家庭设计，若亲缘相似性决定外貌则询问。

需要亲缘相似性时：

1. 整理父母与子女年龄、体态、服装背景、相似和区别。已有确认参考优先。
2. 生成父母基准，视觉检查后展示图片及摘要，等待用户确认。父母顺序可按已有参考选择；两人均需有明确身份。
3. 用户确认后，对父母执行 `approve`，再记录 `GATE_PARENTS`。该 gate.refs 固定为父母已确认版本。
4. 子女版本 dependencies 同时引用父母，gates 包含 `GATE_PARENTS`。实际生图时传入两张图片，明确外貌参考角色和符合年龄的比例。不可只说“像父母”却不传图。
5. 生成子女，展示家庭整体对照，等待确认。`GATE_FAMILY` 引用父母和子女的基准版本。家庭确认后才生成角色变体。

每个变体作为独立资产编号（例如 `CHAR_SON_PROFILE`），dependencies 引用其本人基准，gates 包含 `GATE_FAMILY`。基准本身不依赖引用自己的关卡，避免循环等待。

子女要有独立辨识度，避免父母五官机械拼接、同脸换年龄。父母重做后，关卡失效，子女和关联变体进入复核。保留旧图，不直接覆盖。重新确认后更新所有相关确切版本，再执行待生成队列。

若用户已确定子女形象，则保留子女，反向设计父母；不要强制执行父母先出图。确认可以依据用户之前明确表达的决定，不要求重复确认同一已接受版本。
