# 剧集共享资产与跨集连续性（v0.8）

目录分为剧集共享库和每集独立制作项目，例如 series-library、EP01、EP02。每集保留自己的剧本、改编稿、导演组、分镜、布局、预演和批准。共享库只保存可复用图片的已完成版本与来源快照；不能把第一集整套分镜、台词、心理进程、走位和时间轴直接复制为第二集。

## 第二集从哪里开始

用户说“继续第二集”时，先定位明确的剧集共享库及上集资料；有多个候选且无法判断时再集中询问，不凭同名角色猜共享库。若上集图片从未生成或确认，明确未入库，不以提示词冒充可继承资产。若已授权沿用第一集设定，可直接进行同图继承，不逐张要求用户重新确认同一张图片。

在二次创作前读库目录和真实参考图，写 episode-continuity.md：

- 沿用的风格、身份、年龄、脸型、服装、身材、亲缘关系，以及适用的剧内时间。
- 上集结束位置、持物、湿干、受伤／疲劳、物件损坏状态等；只继承有剧情依据的状态，时间跳跃时重新判断。演员外观相同，不代表本集心理与动作也相同。
- 本集资产表：直接复用的确切版本、需当参考再制作的版本、新增资产及理由。父母与子女的基准及四张人物图分别锁定编号，不能只继承头像后凭空重画全身。
- 场景图与本集布局／机位的核对点。重复场景可以参考原布局，但仍需验证本集动作与取景，不能继承上集“空间已通过”的批准。

将该文登记为 analysis，纳入剧情／改编稿确认。可另维护剧集设定文档 series-bible.md；助手 将实际使用的设定版本复制并登记到每集，记录文件哈希，不把未经用户确认的新设定写成既定事实。当前脚本自动处理图片和来源快照，设定文档由助手编写与登记。

## 第一集资产入库

```sh
.venv/bin/python scripts/svd.py series-init SERIES_LIBRARY --name '剧集名称'
.venv/bin/python scripts/svd.py series-publish EP01 SERIES_LIBRARY --episode EP01 --assets CHAR_LIN_HEAD,CHAR_LIN_FRONT,CHAR_LIN_BACK,CHAR_LIN_LEFT,PROP_PHONE
.venv/bin/python scripts/svd.py series-list SERIES_LIBRARY
```

这是本地入库，不是上传网络。只选已实际生成、当前有效、检查通过、必要用户确认及依赖关卡就绪的资产。无需等待整集最终视频完成。每个外观／状态用稳定资产编号；换装、伤后外观、损坏道具通常新建独立编号，身份基准保持不变。

库版本独立于来源项目的局部版本：library.json 保存共享版本、源集号、源资产版本、原提示词／工具／检查／确认依据及文件SHA-256。重复入库同一快照复用已有版本；更新产生新版本，不覆盖旧图。入库不改变第一集数据，也不让已使用旧版的剧集自动升级。

## 第二集实际继承

完成本集分镜中的资产需求声明后，在 manifest 建立本集待生成资产和互相对应的镜号引用。已经启动审核时，继承只能填充这些同镜号、同类型、尚无图片的待生成版本，不能覆盖已有图片或偷偷修改已审核镜头。新增镜头或引用通过正常分镜修订流程处理。

```json
{
  "episode":"EP02",
  "items":[
    {"source_id":"CHAR_LIN_HEAD","version":1,"target_id":"CHAR_LIN_HEAD","shots":["SHOT_01","SHOT_02"],"mode":"reuse","continuity_note":"与第一集同一时间线，脸型、发型和年龄不变；本集表情在分镜中独立设计。"},
    {"source_id":"SCENE_STORE","version":1,"target_id":"SCENE_STORE","shots":["SHOT_01"],"mode":"reference","continuity_note":"沿用便利店外观，须核对本集门窗、通道和机位方向。","layout":{"id":"STORE","version":1}}
  ]
}
```

```sh
.venv/bin/python scripts/svd.py series-inherit EP02 SERIES_LIBRARY INHERIT_PLAN.json
.venv/bin/python scripts/svd.py series-check EP02
```

- version 是确切共享版本，不接受 latest。target_id 是本集编号，允许显式别名，冲突时拒绝覆盖。
- reuse：用于形态、服装／状态完全相同的人物或道具图片，沿用该图已有的检查和批准，并保留来源依据。仍服从本集已声明的依赖和关卡；这不是对本集分镜、表演和布局的批准。助手 必须实际检查连续性，不能只填一句理由绕过差异。
- reference：导入作为参考候选，图片保留，但检查与批准回到 pending，随后按正常 review／approve 或 revise 处理。
- 场景始终需要本集检查和确认，即使选择 reuse 也不复制空间批准；必须绑定本集真实布局版本及匹配镜号。检查门窗、家具、通道、遮挡、照明和预演方位后才决定直接采用或生成新视角。
- 图片复制到每集自身目录；来源快照登记为 handoff 文档，全部使用项目内相对路径。旧来源依赖作为已核验的历史记录保存，不把第一集的资产／布局编号直接接进第二集运行依赖。复制后的完整项目无需共享库在线即可验证或打包。

网页资产卡显示来源集、共享编号和版本、继承方式及本集检查状态。任何继承图片被改写会被 series-check 和正式 validate／package 检测；不要直接覆盖PNG文件。

## 后续版本与状态变化

第二集需要新衣服、新视角或损坏状态时，保留继承基准，建立独立变体并以其为依赖；需要修订同一资产时使用 revise 保留旧版。新图完成检查与必要批准后再入库，形成可供第三集选择的新版本。第一、二集已经锁定的文件继续保持原样。

共享库不会静默同步本集。要切换库版本，先说明造型／状态变化，建立新的本集资产或修订版本，更新实际引用，重新核对受影响镜头和导演任务。不能因为库里出现新版就撤销过去剧集的已完成成果。
