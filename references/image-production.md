# 生图执行与一致性检查

通过当前环境实际可调用的图像生成工具创建角色、场景与道具参考图；如环境提供相应生图技能，遵循其调用约定。不要求工具名为 image_gen，也不假定各平台的参考图输入和文件返回方式相同。此 Skill 不内置自有生图 API 客户端，也不推测工具背后的模型名称。

人物资产须遵循 [四张独立参考图规格](character-reference.md)：颈部以下正视、含头部背视、含头部左侧视、头部特写。同一身份、服装和体型，逐张生成并独立登记；不以拼图替代。

## 执行范围

按需交付先遵循 [按需交付](on-demand-delivery.md)：无需项目队列、前置阶段、布局或预演。直接查看所用参考、调用工具、检查并保存真实图片；下文 queue、register 与阶段批准适用于完整项目。有现成布局或机位要求时应遵循，无布局时按明确描述制作并说明空间未经三维验证。用户只要求某张人物图时不自动扩成四图。

## 请求准备

1. 读取 `queue`，只处理 ready=true 的资产。让当前版本 prompt 明确：主体、视角、状态、风格、材质、背景、必须保持的特征，以及每张输入参考图的作用。
2. 从 dependencies 找到确切参考版本的文件。查看未见过的本地参考图，按工具实际支持的方式传入参考，不假装仅文字提到文件就等于引用图片。
3. 家庭关卡先满足，再处理子女或变体。准备面部、手部、袖口和道具特写时，以确切镜头需要为依据。
4. 场景按 [预演到场景资产](scene-reference.md) 绑定已确认布局与预演机位／形态。实际传入对应摄影机白模图和已确认美术基准，生成后比对方位、比例、门窗、家具、通道、光源与遮挡；参考输入不保证自动一致。

## 执行与保存

实际调用环境中的图像生成工具，等待并检查结果。不要用 Python 绘图或白模输出冒充角色、场景或道具的最终 AI 图片。Python 在本项目只生成明确的空间示意和几何预览。

工具返回真实图片文件后，用 `register PROJECT ASSET_ID --image ABSOLUTE_IMAGE_PATH --tool TOOL_NAME` 保存。该命令复制原文件而不转换图片内容、创建版本路径、更新生产状态；不覆盖已有版本。依赖变更时先重新检查队列。

人工检查身份特征、年龄、表情、手指与左右手、服装袖口、道具状态、文字和布局。通过后 `review --note`；不通过使用 `review --reject --note`，然后 `revise --reason` 建新版本再重做。已有图不因新版本失败而删除。

基准确认由用户实际回复驱动，`approve` 和 `approve-gate` 只记录已有决定。普通变体通常 approval=not_required，但视觉检查仍要完成。每项默认一次有针对性的纠正；更多重试取决于预算、是否改善及用户已给出的授权。

工具不可用或结果不确定时保留 prompt_ready/failed 状态，说明未完成部分，不自动切换到收费 API。用户明确选择 API 后才另行适配。没有 AI 生图请求时，开发测试只使用隔离的合成测试图片，并标为测试数据，不能作为生产成果交付。
